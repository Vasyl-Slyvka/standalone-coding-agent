# S02b.2 — звірка CLI trace і шлях тестування за €0

**Стан:** виправлено офлайновий аналізатор; живих coding-engine/model запусків немає. Умови користувача: зараз **€0**, API-ключів немає; перша ОС — Windows 10 або Kubuntu, що ще встановлюється. Точну версію Windows, GPU/драйвер, обсяг пам'яті й готовність Kubuntu на цій машині тут **не перевірено**. Scope — [`task-S02B-SOURCE-CHECK.md`](../../tasks/task-S02B-SOURCE-CHECK.md).

## Перевірене в коді, виправлення та тест

На pinned revision [OpenCode `run.ts`](https://github.com/anomalyco/opencode/blob/34aa427434b054afcce7184764aa681159b5d769/packages/opencode/src/cli/cmd/run.ts) `run --format json` **перетворює** внутрішню SSE-подію `step-finish` на рядок `{type:"step_finish", sessionID, part}`. Попередній S02b.1 парсер очікував лише SSE `{type:"message.part.updated", properties:{part}}`, тому пропускав би usage в типовому CLI-потоці. Тепер обидва формати розпізнаються окремо; змішані потоки й кілька CLI sessions у файлі відхиляються. Для Codex pinned [event schema](https://github.com/openai/codex/blob/c98e263fb5365a512bb997a103d6ee8aa14c23e6/sdk/typescript/src/events.ts) містить `cache_write_input_tokens`, який додано до спостережень. Тести — синтетичні події за source schema, **не** захоплені з виконаних інструментів.

У CLI JSON OpenCode є `step_finish` з tokens/cost, але цей потік **не містить `message.updated` із modelID/providerID**. Отже, `model_identity=unresolved`: не можна зробити висновок, що модель збіглася з ручним вибором або відбулася підміна. Для цього потрібен незалежний провайдерський журнал чи окрема SSE-інтеграція, перевірена на живому запуску. `engine_reported_cost_usd` — поле рушія, не рахунок за API; €0 зовнішніх платежів не означає €0 електроенергії або ресурсів комп'ютера.

## Практичний маршрут без платних API, коли ОС готова

1. На своїй машині перевірити версію Windows 10 (для [Ollama Windows](https://docs.ollama.com/windows) нині вказано 22H2+) або завершити встановлення Kubuntu; перевірити RAM, GPU/VRAM, драйвер та вільне місце. Не виводити з назви відеокарти гарантовану швидкодію. Не ставити інструменти/моделі на власну машину користувача віддалено без готового середовища.
2. Вручну вибрати відкриту локальну модель і її версію/розмір, перевірити окремо її ліцензію, підтримку інструментів, контекст і вимоги до ресурсів. [Ollama](https://docs.ollama.com/integrations/opencode) документує інтеграцію з OpenCode; [OpenCode provider docs](https://opencode.ai/docs/providers) — явний локальний endpoint. Це **кандидат** для безплатного smoke test, а не обраний архітектурний backend чи друга незалежна API-служба.
3. Зробити одну коротку задачу у **синтетичному одноразовому repo** зі [стенда S02a](../../benchmarks/README.md) і лімітами контексту/кроків/часу. Не запускати на NODREN. Явно вимкнути auto-approval, автошеринг, приховані фонові моделі, мережеві дії й Git-мутування; перед живим тестом перевірити фактичні параметри поточної версії та ізоляцію shell. Якщо не вдається довести межі — тестувати лише read-only/mock path.
4. Записати версію engine, OS, model ID, local endpoint, конфігурацію без секретів, Git base, tests/diff, error events та потік подій. Звірити `sca.trace_audit` з фактичним JSONL; при доступності Ollama native [usage fields](https://docs.ollama.com/api/usage) порівняти token counts для того самого виклику. Проксі, кешування й допоміжні model calls можуть порушити просте зіставлення; їх треба явно виявити. Журнал не комітити.
5. Далі повторити прийняті задачі й негативні сценарії через ті самі модель/умови для тонкого CLI wrapper і hybrid. Власний API loop оцінити лише якщо дані виявлять, що готовий рушій не дає потрібного контролю. Слабка локальна модель може провалити завдання через обмеження моделі, а не архітектури; **не робити висновку про загальну якість** з одного smoke test.

**Незакритий gate S02b/R1:** €0 local smoke test може перевірити монтаж і частину telemetry/sandbox, але не підтвердить два окремі вручну вибрані API-провайдери з Product DoD, точність хмарних цін чи порівняльну якість моделей. Живого результату в цьому слайсі немає. Наступна дія після готовності ОС: інвентаризація можливостей і ручний вибір локальної моделі для обмеженого synthetic smoke test; не робити вигляд, що другий платний провайдер уже підтриманий.
