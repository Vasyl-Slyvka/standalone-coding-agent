# S03a — ручний вибір моделі без API

**Стан:** офлайновий контракт вибору; живий S02b/R1 відкладено, але gate не закрито. Scope: [`task-S03A-SELECTION.md`](../../tasks/task-S03A-SELECTION.md). Користувач зараз без ноутбука, бюджет тестування €0. У виконавчому Linux-середовищі ~10 GiB RAM, немає GPU, локальної моделі, Ollama чи OpenCode. Доступний Codex CLI сам по собі не підтверджує локальну безплатну inference, ручний вибір і повноту telemetry цього проєкту. Ці факти стосуються лише поточного середовища; висновку про ноутбук немає.

## Контракт

`sca.selection` читає UTF-8 JSON до 16 KiB з **рівно** чотирма полями. Наведені значення — навчальні і не називають затверджений provider/model:

```json
{"schema_version":1,"provider":"example-provider","model":"example/model:v1","endpoint_alias":"local-test"}
```

```bash
PYTHONPATH=src python3 -m sca.selection /path/to/selection.json
```

Вивід містить ті самі значення, SHA-256 канонічного JSON знімка й `status: UNVERIFIED_SELECTION`. Конфіг читається один раз; вже створений `Selection` не змінюється після правки файла. Дублікат ключа, зайве поле (зокрема `api_key`), пропуск поля, `auto/default`, невірна версія та URL замість `endpoint_alias` блокуються. Alias — лише ім'я, **не адреса API**. Ключі не записувати в цей файл; майбутній секретний механізм і зіставлення alias → endpoint потребують окремого рішення.

Жоден model call, network request, inference cost, workspace edit чи перевірка дійсної моделі цим CLI не виконується. SHA-256 визначає вміст знімка, а не доводить, що рушій або API ним скористався. Властивість `frozen` захищає значення об'єкта в одному процесі, але майбутній run повинен зберігати власний snapshot та звіряти його зі справжніми викликами. Цей Python-модуль — маленький незалежний компонент; мову й рушій фінального MVP досі не обрано.

## Межа переходу

Наступна інтеграція потребує живого тесту S02b на синтетичному repo, журналу фактичних дій і незалежного підтвердження model calls. Без цього `R1 → R2` і підтримка двох API-провайдерів залишаються відкритими. Наступні офлайнові компоненти дозволені лише тоді, коли вони не припускають наперед конкретний engine і не видаються за повноцінний S03.

## Перевірка

`PYTHONPATH=src:. python3 -m unittest discover -s tests -v`, `git diff --check`, Python compilation і перевірка локальних Markdown-посилань. Синтетичні тести охоплюють сталість snapshot, зміну конфіга, двозначні або секретні поля та зламаний формат; провайдерські виклики не перевірялися.
